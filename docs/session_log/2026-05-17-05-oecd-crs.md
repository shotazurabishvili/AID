## Goal

Ingest **OECD DAC CRS — the treatment variable** (ODA flows to education) at project-level resolution, preserving everything needed to keep three Pending ADRs open: 0005 (commitment vs disbursement, Phase 5), 0007 (intervention typology, Phase 7), 0008 (China inclusion, Phase 5). No ADR locks this session.

## What we did

- Discovered the OECD CRS bulk-download mechanism by reading the source of `ONEcampaign/oda_reader` (Python). The current bulk file is `CRS-Parquet-v20260408` (1024 MB zipped, 1263 MB uncompressed). The IDFile GUID is dynamic per release; the script discovers it at runtime via the SDMX dataflow XML at `sdmx.oecd.org/.../DSD_CRS@DF_CRS/1.6`, regex-matching the marker `CRS-Parquet-v[^|]*\|...IDFile=([0-9a-fA-F-]{36})`.
- Built `R/10_ingest_oecd_crs.R` mirroring the UIS Session-03 pattern (8 numbered sections, `[oecd_crs]` log prefix, 90-day raw-zip cache, SHA-256 of both zip and extracted parquet).
- **Hit a Deflate64 extraction blocker.** OECD ships the bulk zip with ZIP method 9 (Def64N), which R's `unzip()` and Python stdlib `zipfile` cannot decompress. Resolution: small Python helper (`scripts/extract_deflate64_zip.py`) using the `zipfile-deflate64` PyPI shim, run from a project-local venv at `.venv-tools/` (one-time setup via `scripts/setup_tools_venv.sh`; both committed, venv gitignored).
- **Hit a recipient-code resolution problem.** OECD uses its own area-code system (e.g., Nigeria = OECD 261, not ISO numeric 566). First pass via `normalize_iso3(..., origin="iso3n")` dropped 73% of rows. Switched to `normalize_iso3(recipient_name, origin="country.name")` — drop rate fell to 10.6% (all clean regional aggregates).
- **Hit a schema-mismatch problem.** The `oda_reader` `crs_dotstat.json` mapping is a SDMX-to-dotStat translation table, NOT the actual bulk parquet's column list. The bulk parquet ships in **legacy CRS dotStat format** with separate `usd_commitment` / `usd_disbursement` columns (wide on measure), not a long-format `measure_code` dimension. Revised `KEEP_COLS` accordingly (38 columns including paired `_defl` constant-USD variants, `usd_grant_equiv`, 5-digit `purpose_code`, and all four description-text fields plus `keywords`).
- Final ingest: 601,038 rows in education sector → 537,586 country-level rows × 38 columns × 172 recipient countries × 125 donor identities × 1995–2024.
- Computed (iso3, year) availability contrast for the three measure columns (`has_commitment`, `has_disbursement`, `has_grant_equiv`). SSA gap is **−1.27 pp** (commitments) and **−1.11 pp** (disbursements) — excellent parity. Grant-equivalent measure starts 2015 and is ~68% missing in both groups (post-2018 ODA methodology hasn't fully populated yet).
- Updated documentation layer: methodology §3.5 expanded with the Session-05 confirmation paragraph; data dictionary section added; obligations SHA-256 row bumped to 7/12 hashed (counting `hlo_aap2018` separately).
- Catalog now renders 12 sources (previously 12 already, with `oecd_crs` as a stub; this run populates the row).

## Decisions made

- **No ADR locks this session** — ADRs 0005 / 0007 / 0008 all stay Pending. The ingest preserves all three.
- **Bulk-format choice: full parquet (not reduced)** — description text is non-negotiable for ADR-0007.
- **Resolution choice: project-level** (one row per donor-recipient-year-project-flow-finance). Phase-2 merge aggregates to (iso3, year).
- **ISO3 resolution: via `recipient_name` (`country.name` origin)** rather than `recipient_code` — OECD's area codes are not ISO numeric and a code-based path drops 73% of sovereign-state rows. Name-based path drops 10.6% and they're all clean regional aggregates.
- **Deflate64 toolchain: zipfile-deflate64 in a project-local venv**, not the R `archive` package (which needs `libarchive-dev` apt headers we don't have). `scripts/extract_deflate64_zip.py` + `scripts/setup_tools_venv.sh` are committed; the venv at `.venv-tools/` is gitignored. One-time setup per fresh machine.
- **Pinned `KEEP_COLS` is 38 columns** (legacy CRS dotStat schema). Any change requires an ADR.
