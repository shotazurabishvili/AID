## What we tried that didn't work

*Added retrospectively (template introduced this session). High confidence — within current conversation.*

- **Double-prefix bug on first merge run.** `R/30_merge_panel.R`'s aggregation step produced CRS columns named `crs_commit_usd_sum`, then the generic `prep(., "crs")` helper added the prefix again, yielding `crs_crs_commit_usd_sum`. The join_stats summary caught it: CRS and GCDF showed "0 cells with data in panel" while every other source had data. → Removed the prefix from the aggregation step (column names became `commit_usd_sum`, `disburse_usd_sum`, etc.); let `prep()` add the `crs_` prefix uniformly. Same fix for GCDF.
- **22 duplicate (iso3, year) pairs after the first clean merge.** Verification stopifnot caught it. Root cause: AAP-2018 had sub-national rows (multiple Canadian provinces, Belgian regions, UAE emirates) that all normalized to the same parent ISO3 during Session 04's ingest. The merge inherited the duplicates because we left-join AAP onto the (iso3, year) skeleton. → Aggregated AAP-2018 to `(iso3, year)` mean of `hlo_aap` before the join. 32 sub-national rows collapsed; downstream HLO-cell count shifted slightly (597 → 589) because the original count was inflated by duplicate rows.
- **First viability table looked ambiguous.** I expected 2010-2020 to be obviously superior. The actual numbers showed all three candidate windows produce *identical* Model-2 samples (156 full-row cells × 163 countries × 589 HLO cells) — HLO sparsity is the binding constraint, not window choice. → Escalated to author via AskUserQuestion since it's purely a framing call. Author response synthesized to: 2010-2020 primary + 2000-2022 + 2005-2020 in parallel as robustness.

|---|---|---|---|---|---|---|

All three windows produce identical Model-2 samples (156 cells × 163 countries × 597 HLO obs). Pre-2010 cells are all NA on HLO and contribute zero useful information. The 2010-2020 primary is the densest framing.

**Little's MCAR test** (`output/tables/mcar_test_result.txt`):
```
naniar::mcar_test() on 2010-2020 ∩ ADR-0002 Option-1 (n=1466 rows, 6 cols)
statistic = 1215.975
df = 68
p_value = 0.000000
missing_patterns = 20
```
Strongly rejected. The data is NOT missing at random; missingness is structured by source × time × region. Sets up ADR-0006 (Phase 2 lock): we expect to use listwise on the analytical subset with multiple imputation as sensitivity.

**SSA missingness on the merged panel** (`output/tables/ssa_panel_missingness.csv`):

| Indicator | SSA missing % | Non-SSA missing % | Gap |
|---|---|---|---|
| hlo_hlo_score | 68.2% | 70.0% | −1.84 pp |
| wdi_gdp_pc_usd | 1.08% | 0.20% | +0.88 pp |
| wdi_edu_exp_pct_gdp | 11.5% | 25.0% | −13.5 pp |
| wdi_ptr_primary | 43.9% | 43.1% | +0.81 pp |
| crs_commit_usd_sum | 0.87% | 16.3% | −15.5 pp |
| wgi_ge_est | 0.22% | 0.0% | +0.22 pp |

Counter-intuitive but real: **SSA is BETTER covered than non-SSA** on the analytical columns. Reason: high-income non-SSA countries (US/Europe/Japan/Korea/etc.) are outside the HLO and CRS-recipient measurement universes; on the ODA-eligible subset (which is mostly SSA + South Asia + Latin America), donors and HLO measurement systematically over-target SSA. Worth a §6 Discussion paragraph on the *structural* SSA over-coverage in development-aid measurement universes.
